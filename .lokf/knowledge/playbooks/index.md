# Playbooks

* [Knowledge sources map](knowledge-sources.md) - The librarian's scrape map: every repository location this bundle derives concepts from, the concepts each yields, how to re-check each on a refresh run, and the paths left out on purpose.
* [Regenerate and test after a change](regenerate-and-test.md) - How to change the schema and check it: `uv sync --group dev`, change the converter or the copy, run the converter and the examples writer, then `just gen-project`, `just gen-doc`, `just lokf-adapt`, `just lint` and `just test`, and the pre-commit hooks before a pull request.
* [Cut a release](release.md) - How a release is made: Conventional Commits on `main`, an `## [Unreleased]` changelog section, the `v0.0.0` baseline tag that keeps the first release at 0.1.0, and `semantic-release.yml`, which tags the release and dispatches Knowledge Release to attach `schema-<tag>-uco.yaml` once `KNOWLEDGE_RELEASE_ENABLED` is true.
* [Update the upstream pins](update-upstream-pins.md) - What to do when the weekly upstream watch reports a newer UCO release or tag, a moved tag, a changed or dropped copied file, a changed licence, or a check that could not finish: replace the copy whole from one release, move the pins, rerun the converter and the examples writer, and run the tests.
* [Validate data against the schema](validate-data.md) - How to validate UCO data in the schema's form with `linkml-validate`, one object against its class or a whole document as a `UcoDocument`, and why the validator, not the generated Python models, is the check that applies every constraint.
